# OpenZone Factions

**Steam Workshop:** [OZ_Factions](https://steamcommunity.com/sharedfiles/filedetails/?id=3798436325) · [OZ_Factions_PDA](https://steamcommunity.com/sharedfiles/filedetails/?id=3798436427) · [OZ_Factions_VPP](https://steamcommunity.com/sharedfiles/filedetails/?id=3798436511)

The faction system of the **OpenZone** family of DayZ mods: factions, roles,
ranks, rosters, leadership, permadeath and the admin surface for all of it.

It is a companion of [OpenZone Core](https://github.com/covalschi/openzone-core),
not a part of it. Core knows only the *questions* about a player's affiliation
(`OZ_Identity`: which organisation, which stand towards another player, who
leads) and answers them with "none" on its own; this mod provides the answers.
The same shape carries the spawn loadout: Core strips and dresses
(`OZ_LoadoutService`), this mod decides who wears what.
A server without it runs Core and the PDA exactly as before, just without a
faction tab.

## What is in the box

| PBO | What it does | Needs |
|---|---|---|
| `OpenZone_Factions` | factions, roles, ranks, roster, permadeath, spawn loadouts, its own CF RPC channel (`OpenZone_Factions` / `OZF_RoleReq`), the FACTIONS admin section | Core, the Discord bridge |
| `OpenZone_Factions_PDA` | the **Faction** tab of the PDA (the right half of the contacts screen) | Core, Factions, [OpenZone PDA](https://github.com/covalschi/openzone-pda) |
| `OpenZone_Factions_VPP` | the FACTIONS pane in the VPP Admin Tools window | Core, Factions, `OpenZone_VPP`, VPP Admin Tools |

Each glue PBO is optional and depends on both sides it glues; a server without
the PDA or without VPP simply leaves that PBO out.

### Spawn loadouts

`$profile:OpenZone\OZ_Factions_Loadouts.json` decides what a character wears
when he spawns. Three sections:

- `Presets` -- named sets of items (`Items[]`, each with `ClassName`,
  `SlotName`, `Quantity`, `Health01`, `QuickBar` and a nested `Inside[]`).
- `Ladder` -- rungs, `Faction` + `Rank` -> `Preset`. An empty `Rank` covers the
  whole faction; for an organisation `Rank` is an internal rank slug, for a base
  faction a stalker rank slug. The ladder is walked organisation+rank,
  organisation, base+rank, base.
- `Modifiers` -- per faction, a list keyed by a post or trait slug: `Replace`
  swaps by slot (last one wins), `Add` accumulates.

**An empty ladder means the feature is off**: the mission dresses the character
and this mod does not interfere. That is the state a fresh file is born in, and
the boot line says so (`loadouts: presets=1 rungs=0 ...`).

## Requirements

- **`OpenZone_Factions`** -- [OpenZone Core](https://github.com/covalschi/openzone-core),
  [Community Framework](https://steamcommunity.com/sharedfiles/filedetails/?id=1559212036)
  (`JM_CF_Scripts`), and the [OpenZone Discord bridge](https://github.com/covalschi/openzone-bridge):
  ranks, traits, membership and leadership live in the bot's database. There is
  no "factions without the bridge" configuration.
- **`OpenZone_Factions_PDA`** -- everything above, plus `OpenZone_Factions` and
  [OpenZone PDA](https://github.com/covalschi/openzone-pda).
- **`OpenZone_Factions_VPP`** -- everything above, plus `OpenZone_Factions`,
  `OpenZone_VPP` (OpenZone Core's admin-tab pbo) and VPP Admin Tools.

## Layout

```
OpenZone_Factions/          the mod
OpenZone_Factions_PDA/      glue: PDA tab
OpenZone_Factions_VPP/      glue: VPP pane
ui/                         layout descriptions (tokens come from ../openzone-core/ui/tokens.json -- check the series out side by side)
preview/                    gallery index for the UI eyes of dayz-agentic-modding-mcp
dayz-mcp.toml               build and boot profile (machine paths in dayz-mcp.local.toml, not committed)
packaging/<Mod>/            mod.cpp, meta.cpp -- launcher text and Workshop ids, see packaging/README.md
keys/                       the series' public signing key (OpenZone.bikey); the private half is not committed
package.ps1                 assembles the @Mod folders for the Workshop, see packaging/README.md
```

Generated layouts (first line `// GENERATED by dayz-mcp layout_build`) are
produced from descriptions under `ui/` and are never edited by hand -- the
generator is [dayz-agentic-modding-mcp](https://github.com/covalschi/dayz-agentic-modding-mcp).

## Localisation

Every player-facing string goes through the stringtables: `original` is
Ukrainian, `english` is English, the twelve remaining vanilla columns repeat
the Ukrainian original (the engine needs the full column set). The capital
Ukrainian I is stored as Latin I: no Metron font of the game draws U+0406.
The one exception is `OpenZone_Factions_VPP`: the admin console pane is
English in place, hardcoded, and ships no stringtable of its own.
